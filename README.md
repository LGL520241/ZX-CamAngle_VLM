# CamAngle 摄像头画面巡检系统

通过海康云眸抓图接口批量获取门店监控画面，检查大面积黑灰低纹理区域、模糊、过暗、过曝和倾斜，并将不确定结果交给人工复核。

当前采用 **无基准图方案**。不读取基准图、不做相对移位比对，也不会因为没有基准图就自动转人工。未启用 Qwen 时，基础规则不包含元素语义识别；即使启用 Qwen，画面质量合格也不等于任意业务拍摄区域或绝对摄像头朝向已经确认正确。

## Qwen3-VL 语义巡检

启用 `VLM_ENABLED=true` 后，每张成功抓图会走两层分析：

1. OpenCV 先检查全黑/过曝、模糊、画面倾斜以及黑灰低纹理大面积候选区域。
2. Qwen3-VL-4B-AWQ 判断店外/后厨/收银/用餐/仓库等场景、镜头遮挡、店外朝向以及油锅、收银机、油烟机、柜台、冰箱/冷柜、展示柜/保酥柜、水池、备餐区和员工是否真实可见。员工在收银或打包台前操作会计入命中权重。

Qwen 遮挡面积是辅助证据，不因为估算超过 35% 单独判失败；只有遮挡实际影响监控主体或人员操作时才不合格。前景物体、反光等面积较大但人员和操作仍清楚时应当合格。严重模糊、人员操作无法辨认、对天、对墙和严重倾斜属于硬失败，轻微倾斜不转复核。后厨、后厨+收银和收银场景使用元素命中率；仓库、用餐区和门口人流不参与元素命中评分。业务元素命中率低于 9% 时转人工复核。

最终判定以员工手部和具体操作是否仍清楚可见为核心。Qwen 新增 `hand_action_visible`：只要员工手部、手臂、身体姿态和工作动作清楚，即使面部被强光遮挡、发生普通遮挡或画质异常，也可以按合格处理。对天、对墙和无效场景仍然直接不合格。

如果主分析判断 `obscured` 或主体受影响，系统会额外执行一次“人员操作定向复核”，只判断员工手部、手臂和工作动作，不判断场景、面部或身份。定向复核确认动作清楚时可以覆盖遮挡/模糊结论，复核请求保存在 `.vlm-response.json`。

Qwen 判定严重模糊或严重遮挡时，系统会额外做一次轻量像素交叉校验，专门防止 Qwen 把斜线、固定设备或局部反光误报为全局严重问题。交叉校验仅在 `severe` 时触发，正常图片仍以 Qwen 为主；校验结果保存在 `.quality-guard.json`。

如果 Qwen 成功返回但无法识别任何有效门店场景、且目标业务区域不可见，例如画面几乎全部是近距离墙面、液体或设备表面，则直接判不合格。`camera_type=unknown` 不再被当作服务不可用处理，也不能被人员操作兜底覆盖。

即使 Qwen 给出了室内场景类型，只要目标区域不可见且遮挡状态为 `unknown`，也直接判不合格，避免对墙、对天花板或镜头被近距离物体遮挡的画面进入复核。

Qwen 还会输出 `view_valid`、`view_issue`、`primary_subject_central` 和 `subject_coverage`，用于判断主业务区域是否被充分覆盖。这里的“居中”不要求像素几何居中：固定的操作台、收银台、餐桌椅、货架、入口或通道只要清楚可监控，即使位于画面下部或侧中部也算有效。当前无人、员工暂时离开画面或顾客不在场不构成视角无效，也不能输出 `unknown`。只有目标区域仅剩边缘的一小角、画面主要被墙面/天花板/地面/近物占据时才判无效。主分析显示局部遮挡时，系统还会执行一次中间层空间复核，按“遮挡覆盖目标业务区的比例”判断，不按对象名称或整幅画面面积判断。

每轮巡检目录为：

```text
/mnt/nas/logs/CamAngle_VLM/YYYY/YYYYMM/YYYYMMDD/YYYYMMDD_HHMMSS/
```

文件名以毫秒级抓帧时间、设备序列号和通道号开头，并保存：

- `.jpg`：海康源图
- `.thumb.jpg`：缩略图
- `.occlusion.png`：黑灰候选区域透明标注
- `.cv.json`：OpenCV 中间结果
- `.vlm-input.jpg`：实际发送给 Qwen 的缩放图
- `.vlm-request.json`：模型、Prompt 和输入元信息（不保存 Base64）
- `.vlm-response.json`：Qwen 原始响应、规范化结果和 token/耗时
- `.analysis.json`：最终融合判定
- `run.jsonl` / `cycle.json`：批次进度与汇总

```bash
cd /home/xiaozheng/LGL/CamAngle/CamAngle_VLM
./deploy/start_qwen.sh
./deploy/install_user_service.sh
```

默认 Qwen 输入最长边为 1280，`max-model-len=8192`、`max-num-seqs=24`，vLLM 显存利用率配置为 0.95。8192 上下文用于容纳较长巡检 Prompt、图片 token 和完整 JSON 输出，避免多元素结果在对象中途被截断。VLM 请求默认超时为 180 秒，生产环境建议推理并发不超过 8。
`install_user_service.sh` 会注册用户级 `camangle-vlm-app.service`，支持异常自动重启和开机自启；服务日志写入 `/mnt/nas/logs/CamAngle_VLM/service/app.log`。

完整的场景枚举、元素权重、融合阈值和异常处理规则见 [算法设计](docs/algorithm.md)。

运行设置页提供三个独立模块开关：

- `遮挡面积候选`：OpenCV 黑灰低纹理面积，默认关闭。
- `模糊程度`：OpenCV 分区清晰度，默认关闭。
- `Qwen 语义分析`：场景、语义遮挡、店外朝向和元素命中，默认开启。

当前默认只启用 Qwen。Qwen Prompt 同时估计真实镜头遮挡面积、模糊严重度和人员操作可判断性，OpenCV 遮挡面积与模糊两条链路默认不参与最终判定。业务元素加权命中率低于 9% 时转人工复核，达到 9% 后不再因元素命中率转人工。

运行设置页可以分别编辑 Qwen 的“系统规则 Prompt”和“任务/输出 Prompt”。Prompt 保存到 SQLite，并在每轮巡检开始时生成快照；修改从下一轮生效，不会影响正在运行的批次。

开关组合会在一轮巡检开始时固定，修改后从下一轮开始生效。关闭的模块不会执行计算、请求模型或参与最终判定。

巡检调度提供两条互斥链路，可在 Web 运行设置中切换：

- `coupled`：抓图、下载和单图推理在同一任务中串行执行。
- `decoupled`：第一阶段抓取全部图片并落盘，第二阶段再按独立并发批量执行推理。

解耦链路分别配置抓图并发和推理并发；链路与并发都会在批次开始时固定，从下一轮生效。

3080 实测推荐配置：

```text
抓图并发：16
Qwen 推理并发：24
```

最近一次压测中，抓图并发 16 完成 24/24 张，吞吐约 4.90 张/秒；Qwen 推理并发 24 完成 24/24 张，吞吐约 2.23 张/秒。当前生产配置默认选择 `decoupled`。

## 检测规则

### 黑色 / 灰色区域

`cam_angle/occlusion.py` 按比例将最长边缩小到最多 960 像素，在 HSV 空间提取黑色（V≤32）和灰色（S≤35、V≤220）候选，结合局部亮度标准差、边缘密度和连通区域筛选低纹理块。默认忽略小于整图 0.5% 的零散区域，减少黑点、细线累计误报。

按掩膜真实像素面积除以有效画面面积计算占比，多个有效区域累计，**不使用外接矩形面积**。上下或左右成对出现、单边厚度不超过 20% 的纯黑编码黑边会被识别并排除，不参与遮挡面积和分母。默认严格超过 35% 判不合格；35% 以内的非关键局部遮挡，如果不影响监控主体则可以通过。

这是一条黑灰低纹理面积规则，不能证明物理遮挡。正常灰墙、地面和光滑设备可能触发；彩色遮挡物不在此规则覆盖范围内。当前默认由 Qwen 估计遮挡面积与主体影响，OpenCV 面积候选仅作为可选模块。

### 模糊

`cam_angle/blur.py` 将最长边缩小到最多 640 像素，划分 4×4 分区，排除黑灰异常区域及其边缘。中值滤波抑制噪声，仅在亮度变化、梯度结构足够的区域检查清晰度，避免把纯色表面直接当成失焦。

默认至少 4 个有效分区且有效面积占整图 15% 才能判断。有结构分区中清晰度低于 60 的比例达到 50%，且有效面积至少为 35% 时判模糊不合格；较少分区模糊、强噪声、方向性细节损失（疑似运动模糊）或证据不足转人工。清楚的角落时间水印不能抵消大部分主体分区模糊。

低清晰度比例按有效分区数量计算，不是整图像素面积。极端失焦导致完全没有结构时，该项返回 unknown，由其他质量规则或人工处理。未经真实标注样本校准，规则置信度不代表统计准确率。

### 其他规则与决策

原有全黑、过曝、低纹理、霍夫直线倾斜和基础 SOP 检查继续工作。SOP 当前仅覆盖低纹理，未实现目标语义识别。原先只看整图拉普拉斯方差判模糊的分支已被替换。

有高置信度失败则不合格；低置信度失败、unknown 或 warn 转人工；所有启用项目通过才合格。`baseline.status=skipped` 不参加融合。遮挡与模糊可以同时报告。倾斜检测依赖场景直线水平/垂直的假设，斜货架可能误判。

## 设置

| 参数 | 默认值 | 含义 |
|---|---|---|
| `occlusion_area_ratio` | 0.35 | Qwen 遮挡面积或可选 OpenCV 遮挡候选阈值，严格超过才失败 |
| `occlusion_dark_value` | 32 | HSV 黑色亮度上限 |
| `occlusion_gray_saturation` | 35 | HSV 灰色饱和度上限 |
| `occlusion_gray_max_value` | 220 | 灰色亮度上限，排除接近白色区域 |
| `occlusion_texture_std` | 10 | 局部低纹理标准差上限 |
| `occlusion_min_region_ratio` | 0.005 | 最小连通区域面积比例 |
| `blur_var` | 60 | 规范分辨率下分区清晰度下限 |
| `blur_region_ratio` | 0.5 | 有效分区中低清晰度分区比例阈值 |
| `blur_min_tiles` | 4 | 最少有效清晰度分区数 |
| `confidence_review` | 0.78 | 失败结果低于此置信度转人工 |
| `SAMPLE_SIZE` | 0 | 每轮随机抽取的摄像头数量；0 表示全量 |

运行设置页可调整常用遮挡和模糊阈值。设置接口拒绝非数字、非有限值、越界和冲突配置，保存后重启会恢复。新设置只影响后续分析，历史结果不会被静默重算。初始阈值为经验值，应以实际门店的人工标注结果验证误报和漏报情况。

## 启动与使用

```powershell
# Python 3.9+
pip install -r requirements.txt
python run.py
```

`run.py` 在 20350–20399 自动选择空闲端口，以终端打印的访问地址为准。也可使用已有 `start.ps1` 或 `start.bat`。默认演示模式提供合成相机图片，分析与入库走同一流程。

接入真实海康云眸时，在 `.env` 中配置（示例值不是实际凭证）：

```env
DEMO_MODE=false
HIK_CLIENT_ID=你的client_id
HIK_CLIENT_SECRET=你的client_secret
HIK_BASE_URL=https://api2.hik-cloud.com
HIK_GROUP_NOS=1
```

`.env` 已被 Git 忽略。常用配置还有 `REGION_FILTER`（门店名过滤）、`SAMPLE_SIZE`（0 表示全量）、`DATA_DIR`、`DB_PATH`、`CONCURRENCY`（默认 4）、`CAPTURE_INTERVAL`（默认 5 秒）。完整模板见 `.env.example`。

同一通道抓图至少间隔 5 秒；抓图 URL 应及时下载，设备支持情况及配额取决于云眸账号。同一 NVR 多通道共享带宽。图像分析在工作线程执行，避免阻塞进度接口。

**更新代码后重启服务，开始一轮巡检**，新记录就会包含遮挡和模糊结果。详情中可开关红色标注、查看分区清晰度并人工复核；旧记录缺少新模块时会提示等待下一轮巡检。当前无需建立基准图。原有基准管理接口和历史图查看保留供兼容使用。

## 目录与存储

```text
cam_angle/
  main.py        FastAPI 接口与网页
  pipeline.py    海康抓图、限流、工作线程分析与入库
  analysis.py    无基准分析编排与决策融合
  occlusion.py   黑灰低纹理面积与透明标注图
  blur.py        分区清晰度、噪声与方向性检查
  hikvision.py   海康云眸开放平台客户端
  database.py    SQLite 存储
  config.py      配置、阈值校验与恢复
  demo.py        合成演示图
static/          原生 HTML / JavaScript / CSS
 tests/          图像检测、完整巡检和接口回归测试
```

SQLite 存相机、抓帧批次、抓图、模块结果、复核和设置。每轮巡检创建独立批次，总览、相机判定、抓图和复核默认只统计当前批次，切换批次即可查看历史结果。图片在 `data/images`，缩略图在 `data/thumbs`。每张新抓图旁生成同名 `.occlusion.png` 透明标注，原图不改动；标注导出失败不影响分析结果。整个 `data/` 和备份目录均不入 Git。SQLite 和本地存储适合当前初版，大规模部署需要另行压测和扩容。
