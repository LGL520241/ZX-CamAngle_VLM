# CamAngle VLM 算法设计

## 目标

判断摄像头当前画面是否满足门店业务巡检要求。系统区分三类问题：

1. 画面本身不可用：全黑、过曝、严重模糊、严重倾斜。
2. 镜头被遮挡或朝向错误：大面积遮挡、店外摄像头对天/对墙。
3. 监控主体或人员行为受到影响。

单张图片无法可靠计算云台 pan/tilt 绝对角度。生产判定使用“业务区域覆盖情况”代理摄像头角度是否正确。

## 推理流程

```text
海康抓图
  -> 源图按抓帧时间落 NAS
  -> OpenCV 画质 / 模糊 / 倾斜 / 黑灰低纹理面积
  -> 图像最长边缩放到 1280 后发送 Qwen3-VL-4B-AWQ
  -> 场景、遮挡、室外朝向、固定元素结构化输出
  -> 确定性规则与语义结果融合
  -> pass / fail / review / no_signal
  -> SQLite + NAS 中间日志
```

Web 运行设置可以独立控制三个模块：

- `occlusion`：OpenCV 黑灰低纹理面积候选，默认关闭。
- `blur`：OpenCV 4×4 分区清晰度，默认关闭。
- `qwen_semantic`：Qwen 场景、语义遮挡、店外朝向和元素命中，默认开启。

当前默认只使用 Qwen：遮挡面积、模糊严重度和人员操作可见性都由 Prompt 输出，OpenCV 遮挡和模糊两路默认关闭。
Prompt 可在 Web 运行设置中直接编辑并持久化。每个巡检批次开始时复制 Prompt 快照，下一轮读取最新配置。

流水线在每轮巡检开始时复制一份开关快照，整批图片使用同一组合；设置修改从下一轮生效。

调度链路：

- `coupled`：每个 worker 执行完整流程，适合低延迟和小批量。
- `decoupled`：先完成全批抓图，再执行 Qwen 推理；抓图和推理使用独立并发，适合提高整批吞吐。

两条链路共享同一套视觉判定规则，只改变任务调度方式。

3080 压测结果：

- 抓图并发 16：24/24 成功，约 4.90 张/秒。
- 抓图并发 24：约 4.80 张/秒，出现 1 个设备超时，没有继续增益。
- Qwen 推理并发 24：24/24 成功，约 2.23 张/秒，显存峰值约 19.77GB。

因此默认使用 `decoupled`，抓图并发 16、推理并发 24。

默认 Qwen 模式把 `occlusion_area_ratio` 作为辅助证据。只有 `occlusion_affects_subject=true`，或严重遮挡同时导致主体/操作无法判断时才判不合格。面积超过 35% 但人员和操作仍清楚时可以通过。若手动启用 OpenCV 遮挡模块，仍按单独的 OpenCV 面积规则处理。

## Qwen 固定输出

`camera_type`：

- `store_outdoor`
- `store_entrance`
- `kitchen`
- `cashier`
- `kitchen_cashier`
- `dining`
- `storage`
- `other_indoor`
- `unknown`

`occlusion`：`none / partial / severe / unknown`

`occlusion_area_ratio`：Qwen 估计的真实镜头遮挡面积比例，范围 0–1。

`blur`：`none / slight / severe / unknown`

`operation_visibility`：`clear / partial / obscured / not_applicable / unknown`

`hand_action_visible`：员工手部、手臂、身体姿态和工作台具体动作是否清楚可见。

`outdoor_view`：`proper / facing_sky / facing_wall / unknown`

`angle_quality`：`good / slightly_off / bad / unknown`

固定业务元素：

| ID | 含义 | 权重 |
|---|---|---:|
| `oil_fryer` | 油锅/炸锅 | 0.24 |
| `cash_register` | 收银机/收银屏 | 0.24 |
| `range_hood` | 油烟机/排烟罩 | 0.18 |
| `counter` | 柜台/操作台 | 0.14 |
| `refrigerator` | 冰箱/冷柜 | 0.18 |
| `display_case` | 展示柜/保温柜/保酥柜 | 0.12 |
| `sink` | 水池/清洗槽 | 0.18 |
| `prep_area` | 裹粉/切配/备餐区 | 0.12 |
| `employee` | 员工 | 0.10 |

模型只能从固定列表命中选择，不能返回“炸鸡炉”“收银电脑”等自由类别。Python 层会把模型结果归一化到固定枚举，并补全未命中元素。

## 元素命中率

元素命中率用于后厨、后厨+收银同框、收银和其他明确需要业务元素的室内场景。后厨重点核对油锅、油烟机和操作台。仓库、用餐区以及门口人流场景不参与元素评分。

不同场景使用不同期望元素：

| 场景 | 期望元素 |
|---|---|
| 后厨 | 油锅、油烟机、操作台、冰箱/冷柜、展示柜/保酥柜、水池、备餐区 |
| 收银 | 收银机、柜台、展示柜、员工 |
| 后厨+收银 | 油锅、收银机、油烟机、操作台、冰箱/冷柜、展示柜/保酥柜、水池、备餐区 |
| 收银/其他 | 柜台、员工等通用元素 |

`store_entrance` 是店内或店外门口、进出通道、人流识别摄像头。该场景不要求命中油锅、收银机等餐饮元素。只要进出通道可见、没有局部或严重遮挡，并且没有明确对天、对墙，就认为摄像头角度满足人流识别要求。画面中出现地面或街道属于正常现象，不判为角度错误。

命中率按期望元素的权重重新归一化：

```text
element_score = 命中元素权重之和 / 当前场景期望元素权重之和
```

元素必须满足 `visible=true` 且置信度达到 0.55 才计入命中。

默认决策阈值：

- `element_score >= 0.09`：不再因元素命中率转人工。
- `element_score < 0.09`：必须转人工复核。

## 融合规则

硬失败优先：

1. 全黑、过曝等画质硬失败。
2. 模糊到无法辨认关键细节，或 Qwen 判断人员操作无法判断。
3. 严重倾斜硬失败。
4. Qwen 判断遮挡明确影响监控主体，或严重遮挡同时导致人员操作无法判断。
5. Qwen 明确判断 `severe` 遮挡。
6. 店外摄像头明确对天或对墙。

语义复核：

1. 模糊只影响部分人员操作细节。
2. 室外朝向不明确。
3. 目标区域未确认。
4. 收银、后厨等适用场景的元素命中率低于 9%。
5. Qwen 服务超时、不可用或返回非法 JSON。

轻微倾斜仅记录角度指标，不转人工复核；严重倾斜仍判失败。

人员操作兜底：

- `hand_action_visible=true` 且目标区域可见时，员工手部、肢体和具体操作被视为可判断；遮挡、模糊、倾斜或画质异常不再单独导致不合格。
- 面部和身份不参与该判断，不要求看清员工的脸。
- 主分析认为操作受阻时，追加一次定向操作复核，只检查手部、手臂、身体姿态和工作动作；确认清楚时可以覆盖遮挡/模糊结论。
- Qwen 返回 `severe` 时执行一次轻量 CV 交叉校验，防止把局部物体、线缆或反光误判成全局严重遮挡/模糊；该校验只用于纠错，不参与正常图片的常规评分。
- 明确对天、对墙和无效场景不使用该兜底。
- `camera_type=unknown` 且 `target_area_visible=false` 表示无法识别有效门店场景，直接判不合格。
- 任何场景下，只要 `target_area_visible=false` 且 `occlusion=unknown`，直接判不合格，避免无效视角进入人工复核。
- 已识别场景以主业务区域是否被充分覆盖为准，不要求业务主体几何居中。固定的操作台、收银台、餐桌椅、货架、入口或通道可位于中央、下部或侧中部；只要关键设备、工作区或通道清楚可监控，即视为有效覆盖。
- 当前无人、员工暂时离开画面或顾客不在场不构成无效视角或 `unknown`。固定设施锚点足以证明摄像头仍可监控该区域。
- `primary_subject_central=false` 不能单独触发复核或失败；只有目标区域仅剩边缘一小角、主画面主要是墙/地/天花板/近物，且 `view_valid=false`、区域不可见、元素不足时才判 `camera_view` 无效。
- 主分析返回局部遮挡时，追加一次与对象类别无关的中间层空间复核：估算中间层占画面比例、覆盖目标业务区比例和目标区是否被切断。覆盖目标区达到约 20% 或切断核心工作区时直接判失败；正常线缆、墙面固定屏和场景边界不能仅因面积大而失败。

门口人流场景单独处理：

- 不做油锅、收银机等餐饮元素评分；
- 能看到进出通道且无遮挡时直接合格；
- 35% 以内的非关键局部遮挡，只要进出人流主体仍可见即可合格；
- 明确对天、对墙判失败；
- 地面、街道或室外背景本身不影响合格判定。

## Prompt 设计原则

1. 明确任务是摄像头巡检，不是普通图像描述。
2. 固定场景和元素枚举，减少自由文本类别漂移。
3. 强调灰色墙面、地面、冰箱、金属设备不是镜头遮挡。
4. 店外和门口场景必须判断是否正对门店/进出通道以及是否对天、对墙；看到地面不是角度错误。
5. 元素必须有清晰视觉证据，禁止根据行业常识补全。
6. 不确定必须输出 `unknown`。
7. 使用 vLLM JSON Schema 约束输出，避免 Markdown 和额外解释。

## 资源策略

3080 20GB 实测配置：

- `Qwen3-VL-4B-Instruct-AWQ-4bit`
- 输入最长边 1280
- `max-model-len=8192`
- 运行设置中的抽样数量：`0` 表示全量，正整数表示每轮随机抽取对应数量的摄像头
- `max-num-seqs=24`
- `gpu-memory-utilization=0.95`
- 应用巡检并发 4

24 张图片并发实测：约 3.03 张/秒，GPU 峰值显存约 19.77GB，无 OOM。Web 并发可设置 1–24；8–12 更适合控制单请求延迟，24 适合最大吞吐。
